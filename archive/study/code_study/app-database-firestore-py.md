# app/database/firestore.py

이 코드는 우리 앱의 **'데이터 창고(Google Firestore)'로 가는 길을 열어주는 열쇠**와 같은 역할을 합니다. 

데이터베이스에 접속하려면 "나 허락받은 사용자야"라는 증명(인증)이 필요한데, 이 파일은 다양한 환경(내 컴퓨터, 클라우드 서버 등)에서 그 인증을 어떻게 처리할지 아주 똑똑하게 관리하고 있습니다.

주요 포인트를 4가지로 나누어 설명해 드릴게요.

---

### 1. 싱글톤(Singleton) 패턴: "연결은 한 번만!"
```python
_firestore_client: Optional[Any] = None

def init_firestore():
    global _firestore_client
    if _firestore_client is not None:
        return _firestore_client
```
*   **설명**: 데이터베이스 연결은 비용이 많이 드는 작업입니다. 그래서 이미 연결된 리모컨(`_firestore_client`)이 있다면 새로 만들지 않고 **기존 것을 재사용**합니다. 이를 통해 메모리를 아끼고 성능을 높입니다.

### 2. 3단계 인증 전략: "어디서든 접속 가능하게"
이 코드는 인증 키를 찾기 위해 세 군데를 차례대로 뒤집니다.
1.  **환경 변수 (`FIREBASE_SERVICE_ACCOUNT_JSON`)**: Render나 Vercel 같은 클라우드 서버에 배포했을 때 사용합니다. (보안상 파일보다 환경 변수가 안전하기 때문이죠.)
2.  **로컬 파일 (`serviceAccountKey.json`)**: 내 컴퓨터에서 개발할 때 내 책상 위에 있는 열쇠 파일을 직접 사용하는 방식입니다.
3.  **기본 인증 (ADC)**: 구글 클라우드 자체 기능을 이용하는 방식입니다.

이렇게 짜여 있으면 **"내 컴퓨터에서도 잘 돌아가고, 서버에 올려도 수정 없이 잘 돌아가는"** 유연한 코드가 됩니다.

### 3. 방어적 프로그래밍: "Mock 모드 (가짜 모드)"
```python
_is_mock_mode: bool = False
...
except Exception as e:
    _is_mock_mode = True
    return None
```
*   **설명**: 만약 인터넷이 안 되거나, 인증 키가 잘못되어 데이터베이스에 연결할 수 없다면 어떻게 될까요? 보통은 앱이 에러를 내며 꺼져버립니다.
*   **해결**: 이 코드는 연결에 실패하면 `_is_mock_mode`를 `True`로 바꿉니다. 그러면 앱은 "아, 지금은 진짜 DB를 못 쓰는구나. 일단 임시 메모리에 저장하자!"라고 판단하여 **앱이 죽지 않고 계속 실행**되게 합니다. (매우 훌륭한 예외 처리입니다!)

### 4. 주요 함수 역할
*   **`init_firestore()`**: 데이터베이스와 통신할 준비를 하는 '설치 기사' 역할입니다.
*   **`get_firestore_db()`**: "나 데이터 저장해야 하는데 리모컨 좀 줘!"라고 할 때 사용하는 함수입니다.
*   **`is_firestore_mock()`**: 지금 사용 중인 데이터가 '진짜 클라우드 데이터'인지 '임시 가짜 데이터'인지 확인해줍니다.

---

### 💡 비유로 이해하기
이 파일은 **"은행 금고(Firestore)에 접속하는 보안 팀장"**입니다.
1.  팀장은 금고 열쇠가 **주머니(환경 변수)**에 있는지, **가방(파일)**에 있는지 확인합니다.
2.  열쇠를 찾으면 금고를 열고 **연결 통로(Client)**를 유지합니다.
3.  만약 열쇠를 잃어버렸다면? 당황해서 도망가는 게 아니라, **"일단 임시 보관함(Mock)을 사용하세요"**라고 안내하며 은행 업무가 중단되지 않게 합니다.
