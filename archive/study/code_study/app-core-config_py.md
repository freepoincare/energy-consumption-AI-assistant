# config.py & main.py

제공해주신 코드는 FastAPI 백엔드 애플리케이션의 뼈대가 되는 핵심 설정 파일 2개(main.py와 config.py)입니다.
이 코드는 "AI 기반 개인 전력 소비 비서 API" 서비스의 엔트리 포인트(시작점) 역할을 하며, 크게 **환경 설정 관리(Pydantic Settings)**와 **웹 서버 초기화 및 라우팅(FastAPI)**으로 나뉩니다.

------------------------------

## 1. config.py 구조 설명 (환경 설정 및 보안 관리)

pydantic_settings의 BaseSettings를 활용하여 프로그램에 필요한 환경 변수들을 안전하고 깔끔하게 관리하는 파일입니다. `.env` 파일과 자동으로 연동됩니다.

* 기본 시스템 정보 정의
    * PROJECT_NAME: 서비스 이름인 "Electricity Consumption AI Assistant"가 기본값으로 지정됩니다.
    * VERSION: API의 현재 버전(0.1.0)입니다.
    * ENVIRONMENT: 현재 구동 환경(development, 개발 환경)입니다.
* CORS 설정 및 처리 (cors_origins)
    * 프론트엔드(React, HTML 파일 등)가 백엔드 API에 접근할 수 있도록 허용할 주소 목록(ALLOWED_ORIGINS)을 문자열 형태로 관리.
    * `@property def cors_origins(self) -> List[str]`: 부분은 문자열로 저장된 주소들을 쉼표(,) 기준으로 쪼개서 FastAPI가 인식할 수 있는 파이썬 리스트(['http://localhost:3000', ...]) 구조로 변환해 주는 똑똑한 가공 역할을 합니다.
    * `@property`가 있는 이유
        * 정의: 파이썬 내장 데코레이터로, 메서드(함수)를 '변수(속성)'처럼 호출할 수 있게 만듦.
        * 이유: `settings.cors_origins()` 형태가 아니라 `settings.cors_origins` 형태로 괄호 없이 깔끔하게 가져오기 위함.
        * 역할: 호출되는 순간 내부 로직(문자열을 잘라서 리스트로 변환)이 실행되어 최신 데이터를 가공해 반환함.
    * `def cors_origins(self)`에서 `self`의 의미
        * 정의: 클래스를 통해 생성된 인스턴스 자기 자신을 가리키는 파이썬의 표준 규칙.
        * 이유: 함수 내부에서 클래스가 가진 다른 변수들(예: `self.ALLOWED_ORIGINS`)에 접근하고 읽어오기 위해 반드시 첫 번째 인자로 넣어주어야 함.
* 향후 확장성 고려 (AI 및 파이어베이스)
    * `OPENAI_API_KEY`, `OPENAI_MODEL(gpt-4o-mini)`: 추후 AI 전력 비서 기능을 구현할 때 사용할 OpenAI API 설정 공간을 미리 파놓았습니다.
    * `FIREBASE_...`: 사용자 인증이나 데이터 저장을 위해 파이어베이스를 쓸 수 있도록 공간을 마련해 두었습니다.
* `env_file = ".env"`
    * 소스코드에 비밀번호나 API Key를 직접 적으면 위험하므로, 외부 .env 파일에서 변수들을 자동으로 읽어오도록 지시하는 설정입니다.
* CORS란?
    * 정의: Cross-Origin Resource Sharing (교차 출처 자원 공유)
    * 핵심: 브라우저가 가진 기본 보안 정책(SOP) 때문에, 서로 다른 도메인(출처)끼리는 기본적으로 API 요청·응답이 차단됨.
    * 예시: http://localhost:3000(프론트)에서 http://localhost:8000(백엔드)로 데이터 요청 시 CORS 에러 발생.
    * 해결: 백엔드에서 "이 프론트엔드 주소는 안전하니 접속을 허용한다"고 브라우저에게 공식 허가를 내주는 설정이 필요함 (코드의 CORSMiddleware 역할).
    * 로컬 개발 시 팁 (CORS 에러 주의): 로컬에서 3000과 8000으로 다르게 띄운 상태에서, 프론트(3000)가 백엔드(8000)로 API 요청을 보내면 브라우저가 보안상 요청을 막는 CORS 에러가 발생합니다. 이를 해결하기 위해 로컬 개발 단계에서는 주로 아래와 같이 설정합니다.
        * 방법 A (백엔드에서 허용): 백엔드 코드에서 http://localhost:3000으로부터 오는 요청을 허용(CORS 허용)해 줍니다.
        * 방법 B (프론트엔드 프록시 설정): Vite나 Next.js 설정을 통해 로컬 개발용 프록시(Proxy)를 켜서 3000 포트 안에서 통신하는 것처럼 속여줍니다.
* Class Config
    * 시스템 구동에 필요한 실제 데이터를 담는 곳이 아니라, Pydantic이 환경 변수(.env)를 읽어오는 규칙(파일 이름, 예외 처리 방식 등)을 정의하는 세팅 가이드라인입니다.
    * Class Settings 내부에 Class Config를 선언하는 것은 Pydantic(Settings) 라이브러리가 제공하는 특별한 설정 방식입니다.
    * 실제 파이썬의 일반적인 클래스 상속 구조와는 다르게, "이 Settings 클래스가 외부 환경 변수를 읽어올 때 어떤 규칙을 따를지" 지시하는 설정창 역할을 합니다.
    * `env_file = ".env"`
        * 작동 방식: 애플리케이션이 실행될 때, 루트 디렉토리에 있는 .env 파일을 자동으로 찾아서 읽습니다.
        * 효과: 만약 .env 파일 안에 PROJECT_NAME="My AI System"이라고 적혀 있다면, 코드에 적힌 기본값인 "Electricity Consumption AI Assistant" 대신 .env 파일의 값을 덮어씌워 적용합니다.
        * 장점: API Key나 비밀번호 같은 민감한 정보를 소스코드에 직접 하드코딩하지 않고 외부 파일로 안전하게 분리할 수 있습니다.
    * `extra = "ignore"`
        * 작동 방식: .env 파일이나 시스템 환경 변수 중에, Settings 클래스에 정의되지 않은 다른 변수(예: DB_PASSWORD, AWS_KEY 등)가 있더라도 에러를 내지 않고 무시합니다.
        * 효과: 만약 이 설정이 없거나 extra = "forbid"로 되어 있다면, 클래스에 정의되지 않은 낯선 변수가 주입되었을 때 Pydantic이 *"내가 모르는 변수가 들어왔다"*며 프로그램 실행을 중단(Validation Error)시킵니다.
        * 장점: 다른 용도의 환경 변수가 섞여 있어도 내 프로그램이 튕기지 않고 안정적으로 돌아갑니다.

## 2. main.py 구조 설명 (FastAPI 인스턴스 생성 및 라우팅)

위에서 정의한 설정을 바탕으로 웹 서버를 켜고 구동하는 실제 실행 파일입니다.

* FastAPI 앱 초기화 (app = FastAPI(...))
    * 앞서 설정한 프로젝트 이름, 버전, 그리고 이 API가 무엇인지 설명(description)을 적어 앱을 생성합니다.
    * 여기에 적은 내용이 우리가 아까 이야기했던 Swagger UI(http://localhost:8000/docs) 메인 화면에 예쁘게 타이틀로 표시됩니다.
* CORS 미들웨어 적용 (app.add_middleware(...))
    * 브라우저에서 보안상의 이유로 다른 도메인의 API 호출을 막는 'CORS 에러'를 방지하는 설정입니다.
    * 프론트엔드 개발 서버(localhost:3000 등)가 백엔드에 안전하게 데이터를 요청하고 응답을 받아 갈 수 있도록 허용해 줍니다.
* 헬스 체크 엔드포인트 (/health)
    * tags=["Health"]: Swagger UI에서 이 API들을 그룹화하여 보기 좋게 묶어줍니다.
    * 서버가 현재 죽지 않고 잘 살아있는지 외부 시스템(또는 클라우드 모니터링 툴)이 감시할 수 있도록 현재 상태(healthy)와 서버 환경을 JSON 형태로 반환합니다.
* 루트 엔드포인트 (/)
    * 사용자가 API 주소의 첫 페이지에 접속했을 때 환영 메시지와 함께 **"문서를 보려면 /docs로 가세요"**라는 친절한 안내와 함께 헬스 체크 주소를 안내합니다.
