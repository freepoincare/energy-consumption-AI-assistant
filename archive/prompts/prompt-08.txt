  ### 3. API Communication & Fetch Calls (api.js)

  The frontend consumes all backend endpoints via the centralized ApiService:

  • ApiService.getSummary() ➔ GET /api/data/summary
  • ApiService.listEnergyData() ➔ GET /api/data
  • ApiService.createEnergyData(data) ➔ POST /api/data
  • ApiService.updateEnergyData(id, data) ➔ PUT /api/data/{id}
  • ApiService.deleteEnergyData(id) ➔ DELETE /api/data/{id}
  • ApiService.sendChatMessage(msg, convId) ➔ POST /api/chat
  • ApiService.listConversations() ➔ GET /api/conversations
  • ApiService.getConversation(id) ➔ GET /api/conversations/{id}
  • ApiService.deleteConversation(id) ➔ DELETE /api/conversations/{id}

  Configuration Note: API_BASE_URL is configurable via window.API_BASE_URL or defaults to window.location.origin for local and Vercel/Render deployments.
  ──────
  ### 4. Loading & Error Handling

  • Chat Submissions: The send button is disabled and an animated three-dot bubble (.typing-loader) is inserted into the chat stream while awaiting POST /api/chat.
  • API Errors: If an endpoint fails (e.g. invalid date format or network issue), errors are caught and surfaced via friendly UI alerts or formatted error message
  bubbles (⚠️ Error: ...).
  • Data Validation: Client-side form constraints (e.g. step="0.001", min="0", required) complement backend Pydantic validations.
  ──────
  ### 5. How Conversation History is Loaded

  1. On page load, loadConversations() calls GET /api/conversations and builds the conversation list.
  2. Clicking a conversation triggers selectConversation(convId), querying GET /api/conversations/{convId}.
  3. The chat window clears and sequentially renders the entire messages array.
  4. currentConversationId is set to the selected session, allowing subsequent queries to continue within the same conversation thread.
  ──────
  ### 6. How Summary Data is Rendered

  1. loadSummary() queries GET /api/data/summary.
  2. renderSummary(summary) binds the JSON properties:
      • overall.average_daily_consumption_kwh ➔ #metric-avg
      • overall.total_consumption_kwh ➔ #metric-total
      • extremes.maximum_day / minimum_day ➔ #metric-max / #metric-min
      • trend & cost ➔ #summary-trend / #summary-cost
  3. Any CRUD modification (adding/updating/deleting a daily record) triggers a background call to loadSummary(), instantly refreshing all metrics.
