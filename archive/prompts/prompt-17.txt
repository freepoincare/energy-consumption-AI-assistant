 ### Investigation and Root Cause Analysis

  #### 1. Why were the answers inconsistent across identical requests?

  In the examples from prompt-17.txt:

  • "How much electricity did I use between June 1 and June 15?" gave answers like 66.64 kWh, 66.09 kWh, 66.52 kWh, 66.54 kWh.
  • Actual mathematical sum:
      • June 1 to June 15: 74.112 kWh
      • June 1 to June 14: 69.267 kWh


  When examining the tool execution logs:

  1. When asked about consumption over a custom period, OpenAI chose the tool ai_service.py:57-82.
  2. Previously, get_energy_data_by_period returned a raw list of 15 dictionary items:
    {
      "period": {"start_date": "2026-06-01", "end_date": "2026-06-15"},
      "records_count": 15,
      "records": [{"date": "2026-06-01", "consumption_kwh": 4.864}, ...]
    }

  3. Because no total sum was provided in the tool output, the LLM was forced to mentally perform multi-digit floating-point arithmetic across 15 separate floating
  numbers (4.864 + 4.967 + 4.919 + ... + 4.845).
  4. Autoregressive Large Language Models (LLMs) do not compute math symbolically in their heads; token probability sampling frequently makes slight arithmetic errors
  when summing long sequences of decimal numbers. Because the prompt also specifies CONCISE DIRECT ANSWERS: Skip step-by-step reasoning, calculations..., the model could
  not use chain-of-thought scratchpads to add them column by column. Every request resulted in a slight variation around ~66 kWh instead of the exact total.
  5. In addition, the backend already had a dedicated deterministic statistics tool, ai_service.py:232-280, which computes exact Python-level sums (sum(values) -> 74.112
  kWh), but the tool descriptions and system prompt did not direct the LLM to use it for range totals/averages.
  ──────
  ### What Was Done to Fix It

  1. Precomputed Aggregations in get_energy_data_by_period:
      • Updated ai_service.py:197-235 to calculate and return exact total_consumption_kwh and average_daily_consumption_kwh alongside the list of records.
      • The LLM no longer needs to manually sum rows if it selects this tool.
  2. Refined Tool Definitions & Routing:
      • Updated the description of ai_service.py:83-107 to explicitly state it should be used for total, average, or summary consumption over custom date ranges.
      • Updated the description of get_energy_data_by_period to reflect that it returns precalculated totals and daily records.
  3. Updated System Prompt Tool Selection Instructions:
      • Explicitly instructed the AI assistant in build_system_prompt:
          • To use get_energy_statistics for custom range sums/averages.
          • To rely directly on the tool-provided total_consumption_kwh and average_daily_consumption_kwh without manually attempting decimal addition.
