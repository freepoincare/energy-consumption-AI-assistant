  ### 2. How a Chat Becomes a Saved Conversation

  1. A client sends a query to POST /api/chat with or without a conversation_id.
  2. If conversation_id is omitted, AIChatService automatically generates a new unique UUID.
  3. The AI assistant processes the prompt using the injected energy summary context.
  4. Upon generating the assistant reply, AIChatService invokes ConversationService.record_chat_exchange(conv_id, user_message, assistant_reply):
      • If the conversation does not exist, a new document is created with a meaningful title generated from the user's initial question.
      • If it already exists, the new user and assistant message pair are appended to the messages array, and updated_at is refreshed.
  5. The conversation_id is returned in the ChatResponse payload.
  ──────
  ### 3. How Old Conversations Will Later Be Loaded by the Frontend

  1. Listing Sessions: The frontend calls GET /api/conversations to populate the sidebar with past chat sessions (sorted by updated_at descending).
  2. Selecting a Session: When the user clicks a past session, the frontend requests GET /api/conversations/{conv_id}.
  3. Re-rendering Chat UI: The frontend receives the full messages array and renders the historical message bubbles (user and assistant).
  4. Continuing the Conversation: Subsequent messages sent by the user include the existing conversation_id, seamlessly appending new exchanges to the same thread.
