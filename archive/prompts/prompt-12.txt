[Request]

The required electricity-consumption AI assistant is complete.

Now implement the optional Function Calling / Tool Use bonus.

IMPORTANT DESIGN PRINCIPLE:

Context Injection remains the default.

If the summary contains enough information, GPT should answer from the summary and should NOT unnecessarily call a tool.

If the user asks for information that is not present in the summary, GPT may call an internal application tool.

The goal of Function Calling is NOT to duplicate dashboard/summary questions. It should allow the AI assistant to investigate specific records, periods, and user memos when the summary is insufficient.

For this project, use only the following minimal tools when actually necessary:

1. get_energy_data_by_date

   * retrieves the actual daily electricity consumption record for a specified local date
   * returns the date, consumption_kwh, and memo if available

2. get_energy_data_by_period

   * retrieves daily electricity records for a specified local date range
   * returns date, consumption_kwh, and memo where available

3. get_energy_statistics

   * calculates requested statistics for a specific date range when the existing summary is insufficient
   * use only when genuinely useful

Do NOT create unnecessary tools.

If the existing daily record already contains a memo field, reuse it. Do not create a separate memo system unless the current application architecture requires it.

IMPORTANT AI BEHAVIOR:

The AI should be able to use electricity data together with memo information to investigate possible explanations for changes in consumption.

Examples:

User:
"Why was my electricity usage so high on 2026-07-15?"

→ Call get_energy_data_by_date
→ retrieve the actual consumption and memo
→ answer using both

User:
"I started using the air conditioner around July. Did my electricity usage increase?"

→ Call get_energy_data_by_period and/or get_energy_statistics as necessary
→ use memo information if available
→ compare consumption before and after the relevant date
→ explain the observed pattern

User:
"What might explain the increase in July?"

→ Retrieve the relevant July data and memos if the summary is insufficient
→ identify possible relationships between memo events and consumption changes
→ do NOT claim that a memo proves causation

Use cautious language such as:

* "This coincides with your note that..."
* "This may be related to..."
* "The data shows an increase around this time..."
* "The electricity data alone cannot prove that the air conditioner caused the increase."

Do NOT claim appliance-level electricity consumption because this dataset represents whole-home electricity consumption.

IMPORTANT SECURITY/ARCHITECTURE RULES:

* GPT must never directly access Firestore.
* GPT can only call explicitly defined tools.
* Backend validates every tool argument.
* Tool implementations must use the existing service/repository layer.
* Tool results must come from actual Firestore data.
* Do not hard-code tool results.
* Do not fabricate missing dates or memo contents.
* Do not return data outside the available dataset period.
* Do not log API keys or credentials.

The tool layer must validate:

* date format
* date range
* dataset boundary
* required arguments
* invalid/nonexistent records
* empty results
* reasonable maximum date-range size if necessary

TOOL SELECTION:

Use Context Injection first.

If the answer is already available in the existing summary:
→ answer directly
→ do not call a tool

If the user asks for a specific date:
→ use get_energy_data_by_date

If the user asks about a custom date range or wants to investigate changes over time:
→ use get_energy_data_by_period and/or get_energy_statistics

If the question involves a possible explanation or event recorded in a memo:
→ retrieve the relevant electricity records and memo information
→ compare the memo timing with consumption patterns
→ do not infer causation without sufficient evidence

Example:

User:
"What was my electricity consumption on 2026-08-13?"

Flow:

User
→ GPT
→ determine summary is insufficient
→ get_energy_data_by_date(date="2026-08-13")
→ backend validation
→ Firestore
→ tool result
→ GPT
→ final answer

For:

"Which month did I use the most electricity?"

If the summary already contains the answer:

User
→ GPT
→ Summary
→ final answer

Do not unnecessarily call Firestore.

For:

"I started using the AC in July. Did my electricity usage increase?"

Flow:

User
→ GPT
→ determine summary is insufficient for the requested comparison
→ get_energy_data_by_period(...)
→ backend validation
→ Firestore
→ tool result including memo where available
→ GPT
→ compare periods and explain the observed pattern
→ final answer with appropriate uncertainty
