  ### 1. Firestore Document & Collection Structure
  • Document ID Strategy: Local calendar date string in YYYY-MM-DD format (e.g., "2026-09-01"). This enforces daily uniqueness and prevents duplicate records for the
  same day.
  • Firestore Collection: data
  • Core Stored Record:
      • date (string, required): Local calendar date (YYYY-MM-DD).
      • value (float, required): Daily electricity consumption in kWh.
      • unit (string, default: "kWh"): Measurement unit.
      • memo (string, optional): User notes or activity descriptions.
      • estimated_cost_pence (float, optional): Daily estimated cost in pence.
      • estimated_cost_pounds (float, optional): Daily estimated cost in GBP (£).
      • standing_charge_pence (float, optional): Daily standing charge rate in pence.
      • created_at / updated_at (string, ISO 8601): Timestamps for auditing.

  ### 3. REST API & Firestore CRUD Mapping

   HTTP Method | Route             | Firestore Collection / Document Action          | Behavior & Error Handling
  -------------|-------------------|-------------------------------------------------|-----------------------------------------------------------------------------------
   POST        | /api/data         | db.collection("data").document(date).set(...)   | Validates date/value with Pydantic; rejects duplicates with 409 Conflict.
   GET         | /api/data         | db.collection("data").stream()                  | Fetches all daily documents ordered chronologically.
   GET         | /api/data/{id}    | db.collection("data").document(id).get()        | Returns document or 404 Not Found if nonexistent.
   PUT         | /api/data/{id}    | db.collection("data").document(id).update(...)  | Partially updates value, memo, or cost metrics; returns 404 Not Found if missing.
   DELETE      | /api/data/{id}    | db.collection("data").document(id).delete()     | Deletes document; returns 404 Not Found if missing.
   GET         | /api/data/summary | Query dataset → pass to generate_energy_summary | Generates summary metrics from stored daily records.
  ──────
  ### 4. Credential Management & Security

  Credentials are strictly read from environment variables and never committed to source control:

  1. FIREBASE_SERVICE_ACCOUNT_JSON: In production / cloud environments (such as Render), the complete JSON key string can be stored in this environment variable.
  2. FIREBASE_CREDENTIALS_PATH: In local development, points to a local key file (e.g. serviceAccountKey.json, excluded in .gitignore).
  3. Application Default Credentials (ADC): Secondary fallback for Google Cloud hosting.
  4. Mock / Local Test Fallback: If cloud credentials are not supplied during test execution, the database layer automatically operates with a mock fallback to prevent
  runtime crashes.
