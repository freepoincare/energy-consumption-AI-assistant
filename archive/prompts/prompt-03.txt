  ### 1. Conceptual Explanation: REST API, CRUD & Pydantic in this Project
  1. REST API:
      • Represents electricity consumption records as resource endpoints under /api/data.
      • Uses standard HTTP methods (GET, POST, PUT, DELETE) to express intentions predictably.
  2. CRUD Operations:
      • Create (POST /api/data): Adds a new daily record (date, value, memo) where date is the calendar date, value is daily consumption in kWh, and memo is an optional
      user note.
      • Read (GET /api/data, GET /api/data/{id}): Queries all records or fetches a specific day.
      • Update (PUT /api/data/{id}): Updates consumption values or modifies user notes.
      • Delete (DELETE /api/data/{id}): Removes a record.
  3. Pydantic:
      • Provides runtime type safety and strict request data validation.
      • Rejects invalid date strings, negative kWh values (ge=0.0), or malformed bodies before reaching business logic.
      • Serializes outgoing data into predictable, typed JSON responses.
